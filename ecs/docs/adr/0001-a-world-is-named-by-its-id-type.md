# A world is named by its world ID

A world's type parameter, its world ID, is a named array of words, `type Game [2]uint64`. It names the world, and its values are the world's per-entity component masks, so its size bounds how many component types the world holds. Identification is its main purpose, hence the name `WorldID`; the mask is what lets one type parameter serve both. One kernel can then hold several worlds (a client's simulated and displayed worlds), each with its own resources, and one system can query several. Mask operations are generic over `~[1]uint64 | ~[2]uint64 | ~[4]uint64 | ~[8]uint64` and reach the words through `unsafe.Slice`, so they compile per size and inline. An interface over the mask, or a separate world tag beside a mask parameter, was rejected: the first dispatches on the hot path, the second puts two type parameters on every handle.
